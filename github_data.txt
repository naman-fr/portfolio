Sentinel AI: Radar Array Spacing Predictor 🛰️
A production-grade, Agentic AI platform for optimizing element spacing in 4-element radar arrays to achieve target angular accuracy.

🌟 Features
ReAct Agentic AI Interface: Advanced reasoning-based conversational assistant with modular tool-calling and stateful session memory.
Deep Learning Model: High-performance multi-layer perceptron mapping target RMS angular error to optimal array spacings.
Robust Physics Engine: Multi-frequency Hierarchical Robust CRT Unwrapping and CRLB (Cramer-Rao Lower Bound) theoretical benchmarking.
Digital Twin 3D Dashboard: Immersive Next.js & Three.js interface with interactive 3D tooltips, radome rendering, and real-time radiation pattern (Array Factor) plotting.
MLOps & Observability: Asynchronous background retraining pipeline and integrated Prometheus metrics for real-time monitoring.
Enterprise Architecture: Domain-driven FastAPI routers and SQLAlchemy-backed SQLite persistence for conversational state.

Next.js 14 App Router

Tailwind CSS with custom glassmorphism tokens
Lucide React for consistent iconography

Autonomous Manufacturing Fault Diagnosis and Self-Healing
Production-grade reference implementation for a LangGraph-powered multi-agent system that diagnoses rotating-machinery faults from vibration/RPM signals and emits safety-gated self-healing maintenance plans.

The project is intentionally deployable without an API key: deterministic signal tools run locally, while the agent/tool registry is ready for Claude, GPT, Gemini, Llama, vLLM, or any LangChain-compatible chat model through .bind_tools().

Architecture Diagram

What Is Included
LangGraph StateGraph workflow with cycles, conditional edges, persistence, and a human-review branch.
Supervisor plus specialist agents: Guardrails, DataAug, Detector, Analyzer, RAG, Prescriber, Safety.
A2A communication through typed AgentMessage objects in the graph state.
Six custom LangChain tools bound through bind_manufacturing_tools(llm).
Hybrid retrieval scaffold with BM25 scoring and lightweight ColBERT-style late-interaction reranking.
VAE-WGAN-GP augmentation hook for future trained synthetic fault generation.
Kafka consumer scaffold for streaming SensorWindow payloads.
Streamlit dashboard with CSV upload, Plotly visualization, RAG evidence, metrics, and JSON reports.
MLOps assets: MLflow tracker, Prometheus metrics, Docker, Kubernetes, GitHub Actions, eval harness.
Security layer: local guardrails, prompt-injection checks, email/phone redaction, safety validator.

Production notes:

Run Streamlit separately from graph workers for high-throughput streaming use cases.
Use Kafka for sensor windows and persist graph checkpoints to Redis/Postgres in production.

Keep all maintenance actions advisory until integrated with plant-approved PLC/SCADA controls.

SHL Assessment Recommender
A conversational AI agent that recommends SHL assessments using hybrid retrieval (BM25 + semantic search) with dialogue state tracking.

Quick Start
pip install -r requirements.txt
# Optional: set GEMINI_API_KEY in .env for LLM-powered responses
uvicorn app.main:app --reload
🚀 Live Demo The application is deployed and can be accessed at: https://shl-recommender-uw2d.onrender.com

API Endpoints
Method	Path	Description
GET	/health	Health check → {"status": "healthy"}
POST	/chat	Chat endpoint → {session_id, message} → {response, recommendations}
GET	/	Frontend chat UI
Architecture
User → FastAPI (/chat) → Agent (Intent→Policy→Action)
                              ↓
                    HybridRetriever (BM25 + TF-IDF + optional SBERT/Reranker)
                              ↓
                    SHL Catalog (377 assessments)
BM25: Lexical keyword matching (exact product names, tech terms)
TF-IDF/SBERT: Semantic similarity (intent, role descriptions)
Cross-encoder reranker: Optional precision layer (set USE_RERANKER=true)
Dialogue state: Slot extraction + policy-driven actions (clarify/recommend/refine/compare/refuse)
Evaluation
python tests/test_evaluation.py
Results: 16/16 tests | Recall@10: 0.75 | MRR: 0.65 | 0 hallucinations | 1ms latency

Deployment
Deploy to Render: push to GitHub, connect repo, deploy using render.yaml.

Environment Variables
Variable	Description	Default
GEMINI_API_KEY	Google Gemini API key for LLM responses	(fallback mode)
USE_SBERT	Enable sentence-transformers embeddings	false
USE_RERANKER	Enable cross-encoder reranking	false

🚁 Embedded Cage Drone — Real-Time Flight Control (ArduPilot)
📌 Overview
This project implements a real-time embedded flight control system inside the ArduPilot firmware using Software-In-The-Loop (SITL). The work focuses on low-latency control, sensor fusion, and deterministic execution at the flight-controller level.

Unlike high-level simulations, the controller is integrated directly into the autopilot scheduler, replicating real embedded flight systems.

⚙️ System Architecture
Control Pipeline:

IMU (Gyro + Accelerometer)
        ↓
EKF-based State Estimation
        ↓
Controller (PID / Adaptive PID / LQR)
        ↓
Motor Output (Roll Torque)
Runs inside ArduPilot FAST_TASK scheduler (~400 Hz)
Uses microsecond-level timing (AP_HAL)
Maintains real-time deterministic execution
🧠 Embedded Algorithms Implemented
1. EKF-based State Estimation
Fuses gyro and accelerometer data
Reduces drift while preserving responsiveness
Mathematical model:

roll = roll + (gyro - bias) * dt
roll_acc = atan2(ay, az)
roll = (1 - α) * roll + α * roll_acc
2. PID Controller (Baseline)
u(t) = Kp·e + Ki∫e dt + Kd·de/dt
3. Adaptive PID
Gain scheduling based on error magnitude
Kp = Kp0 (1 + λ|e|)
Kd = Kd0 (1 + γ|e|)
4. LQR Controller (Final)
State vector:

x = [roll, roll_rate]
Control law:

u = -(k1 * roll + k2 * roll_rate)
Derived from cost minimization:

J = ∫ (xᵀQx + uᵀRu) dt

🚀 Overview
EGFL (Enhanced Graph Feature Learning) is an advanced vulnerability detection framework designed for the Ethereum ecosystem. Unlike traditional tools that rely on manual pattern matching, this project utilizes a dual-branch deep learning architecture to analyze EVM Bytecode.

By transforming bytecode into Control Flow Graphs (CFGs), the model captures both the linear execution flow (sequential) and the complex branching logic (structural). This implementation further integrates a Semantic Augmentation Layer to identify high-level design flaws that evade standard opcode-based detection.

🏗️ Technical Architecture
The framework utilizes a multi-stage pipeline to transform raw Solidity code into a security classification:

1. Preprocessing & CFG Generation
Compilation: Solidity files (.sol) are compiled via solc-select to generate uniform EVM bytecode.

📡 Advanced Radar Array Spacing Optimizer
A comprehensive AI/ML-powered solution for optimizing radar array spacing with advanced features including web interface, command-line tools, and detailed analysis.

🚀 Features
AI/ML Optimization: Neural network-based spacing prediction with numerical refinement
Multi-Frequency Support: Optimize for frequency ranges and multiple frequency points
Angle of Arrival (AoA) Range: Support for arbitrary AoA ranges and step sizes
Noise Modeling: Realistic phase measurement noise simulation
Web Interface: User-friendly Streamlit-based web application
Command Line Interface: Full-featured CLI for automation and scripting
Comprehensive Analysis: Detailed performance metrics and visualization
Export Capabilities: JSON and CSV export with timestamps
Physical Constraints: Automatic enforcement of physical limitations
📋 Requirements
pip install -r requirements.txt
Dependencies
numpy >= 1.21.0 - Numerical computations
scipy >= 1.7.0 - Scientific computing and optimization
tensorflow >= 2.8.0 - AI/ML model training and inference
streamlit >= 1.22.0 - Web interface
plotly >= 5.10.0 - Interactive visualizations

🎯 Quick Start

streamlit run app.py

# Basic optimization
python cli_interface.py --target_error 0.1 --freq_min 1e9 --freq_max 1.8e9

# Train new model and optimize
python cli_interface.py --train --target_error 0.05 --num_samples 5000

# Full configuration
python cli_interface.py \
    --freq_min 1e9 \
    --freq_max 2e9 \
    --num_freqs 5 \
    --aoa_min -45 \
    --aoa_max 45 \
    --aoa_step 1.0 \
    --noise_std 0.02 \
    --target_error 0.1 \
    --train \
    --num_samples 3000 \
    --epochs 150 \
    --output results.json
📊 Input Parameters
Frequency Configuration
freq_min: Minimum frequency in Hz (default: 1e9 Hz)
freq_max: Maximum frequency in Hz (default: 1.8e9 Hz)
num_freqs: Number of frequency points (default: 3)
Angle of Arrival (AoA)
aoa_min: Minimum AoA in degrees (default: -60°)
aoa_max: Maximum AoA in degrees (default: 60°)
aoa_step: AoA step size in degrees (default: 0.5°)
Noise and Error
noise_std: Phase measurement noise standard deviation (default: 0.01)
target_error: Desired RMS error in degrees (default: 0.1°)
AI Model Settings
num_samples: Number of training samples (default: 2000)
epochs: Training epochs (default: 100)
batch_size: Training batch size (default: 32)
📈 Output Results
Optimized Spacings
d1, d2, d3: Individual spacing values in meters
Total Array Length: Sum of all spacings
Performance Metrics
Target Error: User-specified target RMS error
Achieved Error: Actual achieved RMS error
Bias: Mean estimation error
Precision: Standard deviation of estimation error
Max Error: Maximum absolute error
Std Error: Standard deviation of errors
Analysis Visualizations
Error distribution histogram
Cumulative error plot
Estimated vs True AoA scatter plot
Array geometry visualization
🔧 Advanced Usage
Programmatic Usage
from radar_optimizer import RadarArrayOptimizer
import numpy as np

# Initialize optimizer
optimizer = RadarArrayOptimizer()

# Configure parameters
freqs = np.linspace(1e9, 1.8e9, 3)
angles = np.arange(-60, 61, 0.5)
noise_std = 0.01
target_error = 0.1

# Train model (if needed)
X, Y = optimizer.generate_dataset(2000, freqs, noise_std, angles)
optimizer.train_model(X, Y, "model.h5", epochs=100)

# Optimize spacings
spacings, achieved_error = optimizer.optimize_spacings(
    target_error, freqs, angles, noise_std
)

# Analyze performance
analysis = optimizer.analyze_performance(spacings, freqs, angles, noise_std)

print(f"Optimized spacings: {spacings}")
print(f"Achieved error: {achieved_error:.3f}°")
Custom Frequency Ranges
# L-band radar
freqs = np.linspace(1.2e9, 1.4e9, 5)

# X-band radar
freqs = np.linspace(8e9, 12e9, 7)

# Multi-band operation
freqs = np.concatenate([
    np.linspace(1e9, 1.2e9, 3),  # L-band
    np.linspace(2e9, 2.4e9, 3)   # S-band
])
🧠 AI/ML Architecture
Neural Network Model
Input: 8 features (error, frequency range, noise, AoA range, etc.)
Architecture: Deep network with residual connections
Layers: 256→256→128→64→3 neurons
Activation: ReLU with Softplus output
Regularization: Batch normalization and dropout
Training Process
Dataset Generation: Monte Carlo simulation with random spacings
Feature Engineering: Comprehensive feature set including physical constraints
Model Training: Adam optimizer with early stopping and learning rate scheduling
Optimization: AI prediction + numerical refinement using L-BFGS-B
Phase Unwrapping
Chinese Remainder Theorem (CRT): Resolves phase ambiguity
Multi-frequency: Leverages frequency diversity for robust estimation
Robust Estimation: Handles noise and measurement errors

Thermal dynamics simulation with discrete temperature updates.
Modular, production-quality Python code with type hints and logging.
Unit tests covering core components to ensure reliability.
Real-Time Telemetry
GPU telemetry using NVIDIA Management Library (NVML) via pynvml for power, temperature, and clock speed.
CPU telemetry using psutil for CPU utilization and frequency.
Asynchronous telemetry collection with background polling threads.
Telemetry data exposed via REST API endpoints for integration with dashboards.
Kubernetes Scheduler Plugin
Energy-aware scheduling decisions integrated into Kubernetes via a custom scheduler plugin.
Collaborative scheduling and telemetry integration for optimized resource usage.

Deployment

Prometheus exporter for metrics collection and monitoring.
CI/CD pipeline configured via GitHub Actions.

Quantum Molecule Simulator
This project is a Quantum Molecule Simulator built using Next.js and Qiskit. It combines quantum computing and machine learning to simulate molecular properties and predict behaviors, providing an innovative platform for researchers and students.

Project Overview
Our platform enables users to:

Simulate molecular energy curves using quantum algorithms like VQE (Variational Quantum Eigensolver).
Predict molecular behavior using a trained machine learning model.
Visualize molecular structures and energy plots.
Explore curated lists of elements and molecules with detailed insights.
This project was developed during a hackathon by Team Bytes.

Features
Quantum Simulations: Leverage IBM Quantum services or local simulators to compute molecular properties.
Machine Learning Predictions: Predict molecular behavior based on complexity, qubits, and other features.
Interactive UI: A user-friendly interface to explore curated molecules and run simulations.
Caching: Efficient caching of results to reduce redundant computations.
Visualization: Generate molecular images and energy plots for better understanding.
Getting Started
Prerequisites
Node.js (v16 or later)
Python (v3.9 or later)
MongoDB (for caching simulation results)
IBM Quantum API Token (optional for quantum hardware simulations)
Installation
Clone the repository:

git clone https://github.com/your-repo/quantum-molecule-simulator.git
cd quantum-molecule-simulator
Install dependencies:

npm install
Set up the backend:

Navigate to the backend folder:
cd backend
Create a .env file and add the following:
MONGODB_ATLAS_URI=<your-mongodb-uri>
IBMQ_API_TOKEN=<your-ibm-quantum-api-token>
Install Python dependencies:
pip install -r requirements.txt
Start the backend server:

python main.py
Start the frontend:

npm run dev
Open http://localhost:3000 in your browser.

Usage
Curated List: Browse a collection of elements and molecules with detailed descriptions.
Simulations: Navigate to the simulation page to run quantum simulations or make predictions.
Details Page: View detailed information about a specific molecule or element.
Team
Frontend Development: Designed and implemented the UI using React and TailwindCSS.
Backend Development: Built the API for simulations and predictions using FastAPI and Qiskit.
Machine Learning: Developed the ML model for molecular behavior predictions.
Visualization: Created molecular images and energy plots for better insights.

Hack the Future | Horizon 2025, IIITV-ICD
Welcome to Hack the Future, the 36-hour online hackathon organized by Coding Club DCodr as part of Horizon 2025, the annual technical fest of IIITV-ICD. This is your chance to collaborate, innovate, and build creative solutions to real-world problems.

Once the hackathon begins, please follow the instructions below carefully.

Instructions for Participants
✅ Step 1: Fork the Repository
Once problem statements are available. Click the Fork button at the top right corner to create a copy of this repository in your GitHub account.
Clone the forked repository to your local machine using the command:
git clone <your-forked-repo-link>
✅ Step 2: Select a Problem Statement
Review the provided problem statements in the PROBLEMS.md.
Choose any one problem statement to work on.
Work directly on the main branch to ensure your final work is on the main branch, as the organizers will evaluate your project every 6 hours.
✅ Step 3: Project Development
Develop your project locally.
Commit your changes frequently with meaningful messages:
git add .
git commit -m "Initial commit with base project setup"
Push your changes to your forked repository:
git push origin main
✅ Step 4: Submission
Create a Pull Request (PR) to this repository before the hackathon ends.
Your repository should contain:
README.md: Instructions to run your project.
Source code and necessary files.
Documentation (if any).
4-5 Page PPT Presentation summarizing your solution to make it easier for judges to evaluate.
Slide 1: Title, team name, and problem statement.
Slide 2: Objective and solution overview.
Slide 3: Key features and technologies used.
Slide 4: solutions implemented.
Slide 5: Challenges faced.
⚠️ Note: Only PRs submitted before the hackathon deadline will be considered. Late submissions will not be accepted.

🔍 Evaluation Criteria
Innovation & Creativity: Uniqueness and originality of the solution.
Functionality & Implementation: Proper execution and working functionality.
Code Quality: Clean, readable, and maintainable code.
Presentation & Documentation: Clear instructions and explanations.
⏱️ Hackathon Timeline
Start: [28/03/2025 5PM]
End: [30/03/2025 5AM]
Duration: 36 hours (continuous online mode)
🚀 Good luck and happy hacking! 🎯

linux-command-terminal
Welcome to the Linux Command Terminal project! This project is a basic terminal (or shell) that lets you type and run simple Linux commands, just like you would in a real terminal on your computer. It's a great way to learn how terminals work behind the scenes!

#About This Project This project creates a small version of a Linux terminal created using data structures where you can type commands, see results, and even handle files and directories. It’s designed to help beginners understand how terminals work by building a simple version themselves.

#Features Run basic Linux commands. Change directories, list files, and view file contents. Handle special commands like cd, exit, and pwd.
